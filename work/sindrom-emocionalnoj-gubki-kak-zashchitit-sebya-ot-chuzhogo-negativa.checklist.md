# Чек-лист статьи «Скилла статей» - `sindrom-emocionalnoj-gubki-kak-zashchitit-sebya-ot-chuzhogo-negativa`

> **Как пользоваться** (ИИ-агент при запуске методологии 16 этапов):
>
> 1. На Этапе 0a: `cp checklists/_CHECKLIST-TEMPLATE.md work/<slug>.checklist.md` + `mkdir -p work/<slug>/`
> 2. По ходу работы - редактируй этот файл, закрывая `[ ]` → `[x]` для каждого выполненного под-этапа.
> 3. **Жёсткое правило.** Галочка `[x]` для пункта со ссылкой на артефакт ставится **ТОЛЬКО** при наличии файла физически в `work/<slug>/`. Нет файла - нельзя ставить галочку. Финальный gate (Этап 16) сверит реальные файлы со списком `checklists/_EXPECTED-ARTIFACTS.txt` через `diff`.
> 4. **Условные пункты** (визуальная QA, hero-картинка, schema-разметка) закрываются как `[x] SKIP: <причина>` - это валидное закрытие.
> 5. **Если инструмент не справился** (например, агент без веб-поиска) - закрывай как `[x] DOWNGRADED-MANUAL: <причина>` И ОБЯЗАТЕЛЬНО создай артефакт вручную (даже если это вывод grep). Это валидное закрытие. Молча подменять инструмент «эквивалентом» запрещено (Этап 0b).
> 6. **Перед Этапом 16.2 (самообучение)** - обязательный gate: `grep -c "\[ \]" work/<slug>.checklist.md` должен вернуть **0**. Не 0 - статья не готова, есть пропущенные этапы.
>
> Этот файл - **единый источник истины** для агента в момент действия. Методология длинная, чек-лист короткий: это то, что агент видит глазами и физически закрывает каждым редактированием, а не то, что он «вроде бы помнит». Внутренний todo-лист обмануть легко, `grep -c "\[ \]"` - нельзя.
>
> Артефакты по этапам: смотри `checklists/_EXPECTED-ARTIFACTS.txt`. Шаблоны заголовка/структуры/черновика: `templates/`. Пороги проверок: `config.yaml` (секция `tools:`).
